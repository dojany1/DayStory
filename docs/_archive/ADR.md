# Architecture Decision Records

## 철학
모바일 사용자가 오늘 카드 한 장을 부드럽게 보는 경험이 최우선. 로그인 없이도 1초 안에 콘텐츠가 보여야 한다. 외부 의존성은 빌드 도구(Vite)와 BaaS(Firebase)만 인정하고, 그 외엔 vanilla 로 충분히 만든다 — 카드 중심 UI는 React/Vue 의 추상화 비용을 정당화하지 못한다. 빠른 반복과 깊은 한 손 조작감을 우선시한다.

---

### ADR-001: Vanilla JS + Vite 채택 (React/Vue/Svelte 미사용)
**결정**: 프레임워크 없이 ESM Vanilla JavaScript + Vite 번들러로 SPA 를 구성한다.
**이유**: 화면 수가 13개 이내로 고정적이고, 카드 1장이 화면 전체를 차지하는 구조라 컴포넌트 트리가 깊어지지 않는다. 프레임워크의 학습/빌드/번들 비용 대비 얻을 게 적다. 직접 만든 `router.js` + `state.js` 합쳐 ~250 줄로 충분.
**트레이드오프**: 컴포넌트 재사용/타입 안전성을 직접 챙겨야 한다. 외부 채용 시 학습 곡선이 React 보다 가파를 수 있음.

### ADR-002: 안드로이드는 Capacitor 로 웹뷰 래핑 (네이티브 직개발 X)
**결정**: 단일 웹 코드베이스를 Capacitor 로 안드로이드 앱(`DayStory.aab`) 으로 패키징한다.
**이유**: 웹/안드로이드를 한 코드베이스로 운영. 위젯/로컬 알림/햅틱/공유는 Capacitor 플러그인으로 충분히 커버. iOS 추후 추가 시에도 같은 방식.
**트레이드오프**: 웹뷰 성능 한계(특히 애니메이션 60fps 보장이 어려움). 네이티브-웹 브릿지 호출은 비동기 — 메인 스레드 동기 가정 코드 금지.

### ADR-003: Hash 기반 SPA 라우터 (`#/path`)
**결정**: HTML5 History API 가 아닌 `window.location.hash` 만 사용.
**이유**: Firebase Hosting 정적 호스팅 + Capacitor 웹뷰 둘 다에서 별도 서버 rewrite 설정 없이 동작. 새로고침/딥링크 모두 안전.
**트레이드오프**: URL 에 `#` 가 노출되어 미관상 손해. SEO 불가(어차피 인증 콘텐츠라 무관).

### ADR-004: Firebase Auth 5초 타임아웃 후 자동 게스트 전환
**결정**: `onAuthStateChanged` 응답을 최대 5초만 기다린다. 그 안에 응답이 없으면 게스트 모드로 강제 전환하고 앱을 진행시킨다.
**이유**: "스플래시 화면에서 영원히 로딩" 사용자 클레임을 차단. 비행기 모드/저전력 모드/네트워크 오프라인에서도 콘텐츠(데모 데이터) 가 즉시 노출돼야 한다.
**트레이드오프**: 5초 안에 인증 응답이 늦은 사용자는 게스트로 시작 후 뒤늦게 로그인 상태로 전환되는 깜빡임이 있을 수 있다. UI 가 그 전이를 자연스럽게 흡수해야 한다.

### ADR-005: 자체 confirmDialog 모달 (`window.confirm()` 금지)
**결정**: 모든 확인/삭제/탈퇴 모달은 `src/js/components/confirmDialog.js` 의 자체 구현을 사용한다.
**이유**: 안드로이드 웹뷰에서 `window.confirm()` 호출 시 Capacitor 라이프사이클 이벤트가 깨져서 백그라운드 복귀 시 페이지 상태가 불일치하던 사례가 있음. 또한 다크 테마/한국어 카피/ESC + 바깥 클릭 닫기를 일관되게 적용해야 함.
**트레이드오프**: 코드 줄 수 증가. 새로운 확인 흐름 추가 시 항상 자체 모달 호출을 잊지 말아야 함 (CLAUDE.md CRITICAL 로 강제).

### ADR-006: 단일 `state` 객체 (외부 상태 라이브러리 미사용)
**결정**: Redux/Zustand/MobX 없이 `src/js/state.js` 의 Pub/Sub 패턴(< 100 줄)을 단일 상태 저장소로 사용. 키 단위 `subscribe`.
**이유**: 공유 상태 키가 ~10개로 적고, 시간 여행/devtools 가 필요한 규모가 아니다. 영속화도 `theme`/`fontSize`/`widgetTheme` 3개뿐이라 직접 처리.
**트레이드오프**: 디버깅 도구가 빈약. 향후 상태가 복잡해지면 마이그레이션 필요. 현재 `state.user` vs `auth.currentUser` 이중 참조 문제는 service 레이어 헬퍼로 흡수할 예정.

### ADR-007: CSS 토큰 단일 소스 (`variables.css`)
**결정**: 색상/간격/z-index/폰트/모바일 폭(430px)/카드 비율 모두 `src/css/variables.css` 의 `:root` + `[data-theme="dark"]` 변수에서만 정의한다.
**이유**: 라이트/다크 토글이 변수 덮어쓰기 한 곳에서 끝난다. Tailwind/CSS-in-JS 도입 없이도 일관성 유지.
**트레이드오프**: PurgeCSS 같은 자동 미사용 토큰 제거가 없음. 수작업으로 정리해야 한다.
